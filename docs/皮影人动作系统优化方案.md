# 皮影数字人动作系统优化方案（v1）

- **状态**：评审稿（待确认后进入 P0 / P1）
- **日期**：2026-11-20
- **适用工程**：`Haining-Shadow-Puppetry-main`
- **基线提交**：`7f7abb2`
- **本阶段只新增文件**：不改现有素材、不改 `actions/*.json`、不改问答 / TTS / 手势链路

---

## 0. 摘要

当前动作系统的问题不在动捕数据，而在**装配层没有真正的影偶机构**：

- 10 个部件各自对齐到外部 17 关节人体骨架，彼此没有父子约束；
- 素材图上的关节间距与驱动骨架的骨长相差 18%~111%（按可见外缘计；上臂不含手仍有 71%，前臂含手、小腿含脚会偏大），远端关节永远对不上；
- 逐角色用 `adjust.json` 的 `pivot / rot / offset` 做静态补偿，大角度即脱节；
- 左右肩相距 102px、左右髋相距 59px，而海宁影偶是**单肩轴、单髋轴**的侧身影偶；
- 动作按 45fps 播放 30fps 数据，整体快 1.5 倍。

本方案把驱动对象从「人体骨架」换成「**影偶关节 + 操纵逻辑**」：

- 保留现有 10 件素材与 15 个动作文件；
- 建立「**单肩轴 / 单髋轴 / 头插口 / 铰链限位**」的 2D FK 骨架；
- **第一目标是不分离**：每片皮子像真实影偶一样被骨眼钉住，只能转、不能被拉长或甩出；限位只负责防反折与过度；
- 动作数据降维为 **12 个受控量**（根平移 2 + 根旋转 1 + 头 1 + 双臂 4 + 双腿 4）；
- 腿保留驱动（按用户决策，追求灵动），只加限位、轻重力与防穿地；
- 侧身约束：永不 3/4，远侧肢体靠图层与同轴叠放处理；
- 先做悟空原型，确认后推广到 4 个角色。

## 1. 背景与目标

### 1.1 现状问题

1. **部件不连通**：`pygame_Alpha.render()` 里每个部件的位置 = 自己的 pose 关键点 + 固定屏幕偏移（`world_x = p1_cur + x_off`），没有层级关系。
2. **图内关节与驱动骨长不一致**（实测见附录 A）：上臂图 145px vs 骨长 85px，前臂 169px vs 80px，小腿 169px vs 97px。
3. **侧面影偶套正面人体骨架**：两肩、两髋分离，远侧肢体像从身体外长出来。
4. **静态补偿不随旋转**：`offset` 是屏幕空间平移，旋转后失效；历史记录里已出现「大角度摆动时部件被甩出、重合/脱节」。
5. **没有铰链限位**：肘、膝可反向折，皮革影偶不可能。
6. **时序错误**：`main.py` 全局 `FPS = 45`，素材 30fps，每 tick 推一帧 → 1.5 倍速。
7. **循环接缝**：`idle` 首尾帧最大关节差 21.3px，每 60 秒跳一次。
8. **历史补丁**：`uses_joint_fix()` 对肘部 +15/+20px、肩部平移 30px，按角色全局生效，属于「按姿态硬凑」。

### 1.2 目标

- **G1 结构真实**：单肩轴、单髋轴、头插口、单向铰链、侧身。
- **G2 装配正确**：任意帧、任意角色，父子关节接缝 ≤ 1px，骨长恒定；**「不分离」是第一验收项**，限位只防反折与过度。
- **G3 动作可复用**：现有 15 个动作全部可迁移，不重录动捕。
- **G4 表现灵动**：腿部保留驱动与抬腿，不做「脚不离线」的被动平移；只加限位与防穿地。
- **G5 可维护**：动作数据从 34 个坐标降为 12 个受控量；新增可视化标定工具，不再靠肉眼凑 `offset`。
- **G6 不破坏现有链路**：问答、TTS、手势、剧本、视频、双人偶全部保持可用；旧渲染保留为 fallback。

### 1.3 非目标（本期不做）

- 不做 3D、不引入物理引擎、不引入第三方骨骼库；
- 不重录真人动捕；
- 不重画素材（真侧面 / 单臂 / 并足的美术改造列为可选项，见 §14）；
- 不拆手掌、脚掌（素材中手与脚分别并入前臂、小腿）；
- 不做文角单臂模式（本期角色均为武角，接口预留）。

## 3. 现状审计

### 3.1 现有渲染链路

```
actions/*.json (17 joints / frame, 30fps)
        │
        ▼
main.py: load_frames()  ── 居中、拼接、可选 joint_fix
        │
        ▼
Puppet.update() ── 每 tick 取一帧，加 current_offset / drag_offset
        │
        ▼
pygame_Alpha.render()
   for each part:
       world = p1_cur + (x_off, y_off)          # 无层级
       angle = get_angle(p1_cur → p2_cur) + ROT_OFF
       blit(rotate(part.png), pivot → world)
```

关键结论：**转角只用于旋转图片，不参与关节定位；部件之间没有长度约束。**

### 3.2 实测问题（详见附录 A）

| 项目 | 实测 | 影响 |
|---|---|---|
| 上臂图内可达长度 / 骨架骨长 | 145 / 85 = 1.71× | 肘部永远对不上 |
| 前臂+手 / 骨长 | 169 / 80 = 2.11× | 腕部外飘 |
| 小腿+脚 / 骨长 | 169 / 97 = 1.74× | 脚部外飘 |
| 大腿 / 骨长 | 140 / 119 = 1.18× | 轻微外飘 |
| 躯干图 / 骨架 | 256 / 197 = 1.30× | 裙摆遮挡，可接受 |
| 左右肩水平距离 | 102px | 侧身影偶不应有 |
| 左右髋水平距离 | 59px | 侧身影偶不应有 |
| 动作骨长波动 | 四肢 0% | 数据干净，可直接转角度 |
| 播放 fps | 45 / 30 = 1.5× | 动作过快 |
| idle 循环接缝 | 21.3px | 每秒/每分钟跳变 |

> 说明：前臂与小腿的「可达长度」包含手和脚，比例会偏大；但上臂不含手仍为 1.71×，足以说明图内关节间距与骨架骨长不一致。

### 3.3 数据现状（好消息）

- 15 个动作的四肢骨长波动均为 **0%**（`upper_neck→pelvis` 有 1~7% 的真人脊柱变化）；
- 说明动作数据本身是「刚性骨长」的，适合直接提取角度；
- 不需要重录动捕，迁移成本主要在骨架标定与动作修整。

### 3.4 历史补丁（迁移时必须处理）

| 位置 | 内容 | 处理 |
|---|---|---|
| `pygame_Alpha.uses_joint_fix()` / `main.load_frames()` | 肘 +15 / +20px、肩平移 30px | v2 禁用，避免与限位/锚点重复叠加 |
| 各角色 `adjust.json` 的 `rot` | −174.3°、−41.5° 等 | 迁移为 `sprite_axis_offset`（常量） |
| 各角色 `adjust.json` 的 `offset` | 屏幕空间平移 | 只保留为骨骼局部空间的美术微调 |
| `prepare_character.py` | 所有部件按身体高统一缩放到 243 | 仅用于生成素材；v2 骨长从素材实际铆钉重新测量 |
| `pygame_Alpha.get_angle()` | `y1 == y2` 时返回 0.0 | v2 不再使用该函数；新角度约定见 §7.4 |

## 4. 真实海宁影偶的结构与操签规律

### 4.1 结构

- 中国非遗网：影人分头、身、四肢，**均为侧影**；演出时**头插于身部**，身与四肢相接，**身部和两手安三根竹扦**。
- 上海博物馆（浙江海宁皮影人）：**影身分 6~8 个部件；除武将为双臂外，其余皆为单臂**；生、净的「身、头」可更换；操纵杆插孔在**头部（头顶或脖口）和手腕**。
- 海宁风格关键词：**少雕镂、重彩绘、单线平涂；单手、并足、侧身；五分脸；头与躯干分离（全国独有）**。
- 通用影偶 11 件：头、胸、腹、双臂上下节、双手、双腿（腿脚一体）；关节刻**骨缝**，连接点为**骨眼**。
- 真实关节是**线缀 / 枢钉**的平面铰链，**单向、幅度有限**。

### 4.2 操纵

- 三根签：**主签**（脖签，管重心、高低、进退、朝向）+ **两根手签**（管手臂）；
- 口诀：**「主签先定位，手签补细节」**；
- 头可小幅转动；转身是**三签同步、整体翻 180°**，不是转身 3/4；
- 传统影偶**腿无签**，腿随躯干被动摆动；要抬腿需另装脚签、两人配合。

### 4.3 行走与身段

- 传统无脚签行走：**没有迈腿动作**，靠双臂前后摆 + 主签平移，双脚贴地平线，行内称「登角」「脚不离线」；
- 文戏稳、武戏猛；动作幅度略大于真人；情绪靠身段与手势（怒抖腕、喜扬身、悲垂手）；
- **贴幕**：轻贴不悬空、不压实。

### 4.4 与本项目的对应

| 真实结构 | 本项目 | 结论 |
|---|---|---|
| 头 / 身 / 四肢，侧影 | 10 件 PNG，头身分离 | 部件数足够 |
| 文角单臂、武角双臂 | 四角色均为武角 | 双臂合理 |
| 6~8 件（海宁）/ 11 件（通用） | 10 件（手并入前臂、脚并入小腿、胸腹合并） | 简化可接受 |
| 单肩轴、单髋轴 | 双肩、双髋关键点 | **需改** |
| 三签 | 17 关节全主动 | **需改** |
| 单向铰链 | 无限制 | **需加** |
| 侧身、五分脸 | 近正面数据 + 镜像 | **需约束** |
| 腿无签、登角 | 人体步态 | **按 D2 保留驱动，不采用登角** |

## 6. 设计决策

### 6.1 决策记录

| 编号 | 决策 | 说明 |
|---|---|---|
| D1 | 采用**单肩轴、单髋轴** | 两臂 / 两腿同点钉结，靠 `DRAW_ORDER` 分远近 |
| D2 | **腿保留驱动**，不做被动钟摆、不做脚锁地平线 | 用户明确要求「灵动一点」；抬腿、迈步、踢腿保留 |
| D3 | 只加**铰链限位 + 轻重力 + 防穿地** | 限位是硬约束；重力只做下垂偏置；地面是软约束 |
| D4 | 头部采用**插口子节点**，±10° | 可锁 0；为未来换头预留 |
| D5 | **侧身约束**，永不 3/4 | 同轴、单侧朝向、翻面用整体镜像 |
| D6 | 部件数保持 **10 件** | 不拆手掌 / 脚掌 / 胸腹 |
| D7 | 动作格式升级为 **actions_v2（角度）** | 旧 `actions/*.json` 原样保留 |
| D8 | 先做 **悟空** 原型，再推广 4 角色 | 武角、双臂、动作最全 |
| D9 | **「不分离」优先于「幅度小」** | 真实影偶每片都打孔、穿线/铆钉固定，关节只能转、不能拉开；限位只防反折与过度，不为了保守而绑死动作 |

### 6.2 关键取舍：腿为什么保留驱动

真实皮影没有脚签，走路是「登角」平移，脚不离线。这最像皮影，但动作观感偏「飘」、不够灵动；项目中打戏、舞蹈、跳跃占比高，用户明确选择**灵动优先**。

因此本方案：

- **结构上**仍然忠实：两腿同髋轴、单向膝铰链、脚与小腿一体；
- **驱动上**做艺术化取舍：髋角、膝角由数据驱动，允许抬腿、迈步、踢腿；
- **约束上**补回真实感：膝不反折、髋不过度、脚不穿舞台线、躯干不 3/4；
- 预留 `leg_mode: driven | glide`，未来文戏慢走可一键切回「登角」。

### 6.3 与真实结构的偏离清单（显式记录）

| 偏离 | 原因 | 影响 |
|---|---|---|
| 腿有驱动、会迈步 | 用户要求灵动 | 不如传统登角「稳」，但更活泼 |
| 双脚允许离地 | 同上 | 需要防穿地约束 |
| 手并入前臂、脚并入小腿 | 现有素材 | 手腕 / 脚踝不可独立转 |
| 胸腹合并为一件 | 现有素材 | 不能弯腰，只能整体倾 |
| 双臂同时可见 | 武角设定 | 远臂靠图层压后 |
| 素材偏 3/4 | AI 生成素材限制 | 骨架上做侧身约束，造型仍非纯五分脸 |

## 7. 目标骨架规格 v1

### 7.1 部件与层级

```
root（骨盆 / 主签基准点）
└─ torso（刚体，颈←→骨盆为躯干轴）
   ├─ head（脖口插口，子节点）
   ├─ shoulder_axis（单肩锚点）
   │   ├─ right_upper_arm → right_forearm(+hand)   # 近侧 / 前层
   │   └─ left_upper_arm  → left_forearm(+hand)    # 远侧 / 后层
   └─ hip_axis（单髋锚点）
       ├─ right_thigh → right_shin(+foot)          # 近侧
       └─ left_thigh  → left_shin(+foot)           # 远侧
```

- `right_*` 定义为**近侧 / 前层**，`left_*` 为**远侧 / 后层**（与现有 `DRAW_ORDER` 一致：`right_elbow=4`，`left_elbow=1`）。
- 头、双臂、双腿都是躯干的子节点；躯干是唯一根。
- 肩锚点、髋锚点在**躯干图片像素坐标**中定义；头插口同理。

### 7.2 锚点与骨长

每个部件只需要两个点：

| 点 | 含义 | 来源 |
|---|---|---|
| `pivot` | 近端骨眼（关节孔） | 部件图像素坐标，可在标定工具中点取 |
| `tip` | 远端骨眼 | 同上 |

- **骨长 = |tip − pivot|**，直接从素材测量，不再使用动作数据里的骨长。
- 上臂、大腿两端的铆钉孔在素材上清晰可见，可半自动检测 + 人工确认。
- 前臂 / 小腿的「tip」取腕签孔 / 踝关节位置（不是图形最外缘），避免把手掌、靴尖算进骨长。
- `sprite_axis_offset`：素材的「向上轴」与骨骼方向的固定夹角，迁移自旧 `adjust.json` 的 `rot`，一次固化。
- `offset`：只保留为骨骼局部空间的美术微调（≤ 数像素），不承担关节对齐。

### 7.3 自由度与限位

**首要原则：先保证「不分离」，再谈「幅度」。**

真实影偶的每一片皮子都在骨眼处打孔、用线或枢钉固定，关节只能绕着钉子转，不能被拉长、不能飞出去。数字版必须复现的也是这一条：

- 父子部件之间的**距离由素材骨长固定**，任何帧都不允许出现缝隙或拉伸；
- 关节角度只是「绕钉子转多少」，限位是**第二优先级**，只负责防止肘 / 膝反折和明显不合理的过度；
- 因此限位可以给得宽松，武角仍能抬腿、踢高、大开大合；只要不反折、不脱节即可。

| 部位 | 自由度 | 驱动量 | 限位（宽松，仅防反折 / 过度） |
|---|---|---|---|
| 躯干 | 3 | `root.x`, `root.y`, `torso.rot` | 前倾 / 后仰 −25° ~ +25° |
| 头 | 1 | `head.tilt` | −10° ~ +10°，可锁 0 |
| 右上臂 | 1 | `arm.right.shoulder` | −40° ~ +155°（后摆不过背） |
| 右前臂 | 1 | `arm.right.elbow` | 弯曲 0° ~ 150°，单向 |
| 左上臂 | 1 | `arm.left.shoulder` | 同右 |
| 左前臂 | 1 | `arm.left.elbow` | 同右 |
| 右大腿 | 1 | `leg.right.hip` | −35° ~ +110°（踢腿动作可覆盖到 +130°） |
| 右小腿 | 1 | `leg.right.knee` | 弯曲 0° ~ 140°，单向 |
| 左大腿 | 1 | `leg.left.hip` | 同右 |
| 左小腿 | 1 | `leg.left.knee` | 同右 |

合计 **12 个受控自由度**（3 + 1 + 4 + 4）。

限位可按行当预设：

| 行当 | 肩 | 肘 | 髋 | 膝 | 躯干 |
|---|---|---|---|---|---|
| 武角（本期） | −40~155 | 0~150 | −35~110（踢 130） | 0~140 | −25~25 |
| 文角（预留） | −25~120 | 0~120 | −25~85 | 0~110 | −15~15 |

### 7.4 角度约定

- 画面坐标：x 向右、y 向下。
- 骨骼方向角：`φ = atan2(dx, dy)`，`dx = tip.x − base.x`，`dy = tip.y − base.y`。
  - `φ = 0°`：朝下；`+90°`：朝角色面向（画面右）；`−90°`：朝后；`±180°`：朝上。
- 关节角 = 子骨 `φ` − 父骨 `φ`，归一化到 (−180°, 180°]。
- 躯干角 = 颈→骨盆方向的 `φ`；直立为 0°。
- 手臂：肩角 = 上臂 `φ` − 躯干 `φ`；肘角 = 前臂 `φ` − 上臂 `φ`。
- 腿：髋角 = 大腿 `φ` − 躯干 `φ`；膝角 = 小腿 `φ` − 大腿 `φ`。
- 头：`head.tilt` 为相对躯干「向上轴」的偏转，0° = 与躯干同轴。
- 单向铰链：`rest.json` 里为每个肘 / 膝存 `hinge_sign`（+1 / −1），限位按「弯曲量 0~max」处理，避免左右侧符号混淆。
- 旧的 `get_angle()` 不再使用；其水平分支 bug 随之消失。

### 7.5 侧身与远近

- **单轴**：两臂共用 `shoulder_axis`，两腿共用 `hip_axis`；同轴点处给 2~4px 的横向微偏，仅为图层可读性，不改变结构。
- **远近**：`DRAW_ORDER` 决定前层 / 后层；远侧肢体自然被躯干遮挡。
- **朝向**：角色只朝右（或整体镜像朝左）；不做左右肩分离，不做 3/4 转身。
- **后摆限制**：肩角下限 −40°，避免手臂甩到背后；若源数据出现明显背向，转换时钳制。
- **翻面**：整体镜像 + 位移取反（沿用 `_mirror_clip_motion` 的思路），不是逐关节转 180°。

### 7.6 重力与地面

- **重力**：只做轻微下垂偏置。静止 / 无驱动帧，肢体角度向「自然下垂」回正；动作帧允许数据覆盖。不引入物理积分，保证确定性。
- **地面**：舞台线 `stage_line_y` 为软约束；画面坐标 y 向下增大，因此要求任意可见像素的 `max(y) ≤ stage_line_y + 2px`（允许 2px 容差）。若穿透，整体上抬 root（减小 y），而非改关节角。
- **跳跃 / 踢腿**：允许双脚离地；落地帧由动作数据给出 root.y。

### 7.7 渲染顺序

沿用现有 `DRAW_ORDER`，并明确语义：

| 层 | 部件 |
|---|---|
| 后 | `left_elbow`（远上臂）、`left_hip`（远大腿） |
| 中 | `head`、`body`、`left_wrist`、`left_knee` |
| 前 | `right_hip`、`right_knee`、`right_elbow`、`right_wrist` |

实际值以 `adjust.json` 的 `draw` 为准；v2 只解释含义，不改数值。

### 8.3 旧格式映射

| 旧 | 新 |
|---|---|
| `frames[].joints`（17 点） | `frames[].root/head/arm/leg`（12 个受控量） |
| `video_info.fps` | `fps` |
| `video_info.resolution` | `canvas`（写入 `rest.json`） |
| `pelvis` | `root.x/y` |
| `upper_neck→pelvis` | `root.rot`（躯干角） |
| `neck→head_top` | `head` |
| `shoulder→elbow`, `elbow→wrist` | `arm.*.shoulder`, `arm.*.elbow` |
| `hip→knee`, `knee→ankle` | `leg.*.hip`, `leg.*.knee` |
| 左右肩 / 髋坐标 | 丢弃；只保留方向角，锚点由 `rest.json` 决定 |

### 8.4 17 个点怎么变成 12 个受控量

先澄清：**17 是「测量点」，12 是「控制量」，不是同一类东西，不能直接相减。**

- 17 个点 = 每帧 34 个数字（x、y 各一个）；
- 12 个受控量 = 2 个根平移 + 1 个根旋转 + 1 个头角 + 8 个关节角。

为什么能少这么多？因为影偶是**定长刚片**：一段骨头的长度固定，知道它的起点和角度，终点就算出来了。旧数据把两端都记下来，等于同一段骨头记了两遍；一旦两端距离和素材对不上，就会拉伸/脱节。新格式只记角度，终点由「起点 + 角度 + 固定长度」推出来，所以永远不会分离。

逐个点看：

| 旧点 | 新方案里的用途 | 是否每帧存 |
|---|---|---|
| `pelvis` | 根的 x、y | 存（`root.x/y`） |
| `upper_neck` | 躯干方向 | 只用来算躯干角 |
| `thorax` | 躯干中间点 | 不存：躯干是整片刚体，中间点没有独立自由度 |
| `head_top` | 头方向 | 只用来算头角 |
| `nose` | 脸的一部分 | 不存：不是关节，头是整片 |
| 左右 `shoulder` | 手臂起点 | 合并成**一个肩锚点**，固定在躯干上 |
| 左右 `elbow` | 肘的位置 | 只用来算肩角 / 肘角 |
| 左右 `wrist` | 腕的位置 | 不存：手与前臂一体，腕点由肘 + 前臂长度算出 |
| 左右 `hip` | 腿起点 | 合并成**一个髋锚点**，固定在躯干上 |
| 左右 `knee` | 膝的位置 | 只用来算髋角 / 膝角 |
| 左右 `ankle` | 踝的位置 | 不存：脚与小腿一体，踝点由膝 + 小腿长度算出 |

所以「少掉的点」分三类：

1. **纯多余**：`nose`、`thorax` —— 不是关节，或没有独立运动；
2. **两对合并**：左右肩 → 单肩轴；左右髋 → 单髋轴；
3. **末端变成算出来的**：左右腕、左右踝 —— 手 / 脚已经并在前臂 / 小腿里，没有独立关节。

**没有丢掉任何影偶能做的动作。** 旧数据里那 17 个点只是用来「量方向」；新格式把量出来的方向存下来，把可以由长度推出来的位置扔掉。

## 9. 运行时设计

### 9.1 求解流程

```
pose (12 个受控量：root + head + arm + leg)
  │
  ├─ 躯干：root → 平移 + 旋转 → 求出 neck / pelvis / 肩锚点 / 髋锚点
  ├─ 头：脖口插口点 + 躯干角 + head.tilt → 头部件变换
  ├─ 手臂：肩锚点 + 上臂角 + 肘角 → 局部 FK → 两个部件变换
  ├─ 腿：髋锚点 + 髋角 + 膝角 → 局部 FK → 两个部件变换
  ├─ 限位：钳制各关节角（只影响显示，不回写数据）
  ├─ 地面：计算可见最低点，必要时整体上抬 root
  └─ 输出：{part: {pivot_world, angle, sprite_axis_offset, draw}}
```

- **纯函数、无状态**：同一份 pose + rest 恒定输出，便于回放和测试。
- 重力偏置在求解前施加（角度回正），不参与跨帧积分。
- 2-bone IK 只在未来「签子交互」时使用；本期运行时用 FK，稳定且无奇异点。

### 9.2 性能

- 每个角色每帧 10 次旋转 + 10 次 blit，与现状同量级；
- 可选按角度缓存旋转后的 Surface（±1° 粒度），降低 `pygame.transform.rotate` 开销；
- 目标：单角色求解 + 渲染 ≤ 8ms @1440×900（与现状对比测量）。

### 9.3 兼容与回退

- 新增 `rig.py` 与 `puppet_rig` 开关，默认先关闭；悟空原型验证通过后，按角色开启。
- 旧 `pygame_Alpha.render()` 保留不动，作为 fallback。
- 旧 `actions/*.json` 不删除、不改写。
- 旧 `adjust.json` 保留，v2 从它迁移 `pivot/rot/draw` 初值。

## 10. 动作迁移

### 10.1 转换算法

对每个旧动作的每一帧：

1. 读取 17 关节；
2. 躯干角：`φ(neck → pelvis)`；`root = pelvis`；
3. 头：`head = φ(neck → head_top) − (躯干角 + 180°)`，钳制到 ±10°（直立时躯干角为 0°，头部骨朝上为 180°，相减为 0°）；
4. 每侧手臂：
   - `shoulder = φ(shoulder → elbow) − φ(躯干)`；
   - `elbow = φ(elbow → wrist) − φ(shoulder → elbow)`；
5. 每侧腿：
   - `hip = φ(hip → knee) − φ(躯干)`；
   - `knee = φ(knee → ankle) − φ(hip → knee)`；
6. 按 §7.3 钳制；
7. 归一化到 30fps（若源 fps 不同）；
8. one-euro 低通平滑（可选，默认开启，减少抖动）；
9. 写入 `actions_v2/<name>.json`，`leg_mode = driven`。

注意：

- **只取方向，不取距离**；左右肩 / 髋的位置信息全部丢弃；
- 若某侧关节缺失或置信度低，用对侧镜像或上一帧角度补齐；
- 源数据接近正面时，左右臂可能都朝画面同侧；转换后按限位钳制，不做额外翻转。

### 10.2 逐动作策略

| 动作 | 躯干 | 手臂 | 腿 | 备注 |
|---|---|---|---|---|
| idle | 轻微摆动 | 自然下垂 + 微动 | 接近 0，脚贴地 | 修接缝 |
| normal | 同 idle | 同 idle | 同 idle | 可复用 idle 的腿 |
| greet / dun | 前倾 | 拱手 / 行礼角度 | 接近 0 | 加亮相 hold |
| dance | 摆动 | 大幅 | 小幅 | 保留节奏 |
| scratch | 稳定 | 单臂上抬 | 接近 0 | 手部高频抖动 |
| forward / back | 平稳 | 前后摆 | 保留迈步 | 限位 + 防穿地 |
| jump | 上升 / 下落 | 上扬 | 收腿 | root.y 弧线 |
| punch | 前倾 | 收拳→打出 | 稳定 | 手签路径保留 |
| kick | 后仰 | 平衡 | 髋 + 膝，允许踢高 | 临时放宽髋限位 |
| block | 下沉 | 交叉抱架 | 微屈 | 加 hold |
| lunge / retreat | 前倾 / 后仰 | 前后摆 | 弓步 / 后撤 | 保留位移 |
| hit | 后仰 | 张开 | 踉跄 | 躯干限位内 |

### 10.3 清洗与手工修整

- 自动：限位、平滑、脚不穿地、首尾接缝；
- 手工（少量）：踢腿、跳跃、亮相停顿、打戏节奏；
- 工具：`tools/preview_compare.py` 输出旧 / 新并排视频，逐动作验收。

## 13. 验收标准

### 13.1 几何（第一优先级）

- **不分离**：任意动作、任意角色、任意帧，父部件 `tip` 与子部件 `pivot` 的世界坐标误差 ≤ **1px**；
- 各部件骨长漂移 **0%**（由 FK 保证）；
- 同轴点：左右肢体根部重合（允许 2~4px 图层错位）；
- 任何情况下不得出现「部件被拉长、甩出、与身体脱开」。

> 限位是第二优先级：只要求肘 / 膝不反折、不出现明显不合理的过度，不为了保守而限制动作幅度。

### 13.2 约束

- **反折帧数 = 0**（肘 / 膝不能往反方向折）；
- 可见最低点 `max(y) ≤ stage_line_y + 2px`（不穿舞台线，允许 2px 容差）；
- 肩后摆不超过 −40°；躯干不出现 3/4 朝向；
- 幅度类限位允许按动作临时放宽（例如踢腿），放宽不等于允许分离。

### 13.3 时序

- 片段时长 = `帧数 / fps` ±1 帧；
- 不再出现 45fps 播放 30fps 的 1.5 倍速；
- `idle` 循环接缝 ≤ 2px（含混合）。

### 13.4 视觉

- 15 个动作 × 悟空：旧 / 新并排盲评，至少满足：
  - 无脱节、无外飘、无穿模；
  - 抬腿、出拳、踢腿可辨认；
  - 侧身成立，不出现「双肩张开」；
- 通过后再推广到 4 角色。

### 13.5 工程

- 现有问答 / TTS / 手势 / 剧本 / 视频 / 双人偶链路无回归；
- 旧渲染可一键回退；
- 新增代码不引入第三方依赖。

## 14. 风险与待定项

### 14.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 素材骨眼位置不清晰 | 骨长误差 | 半自动检测 + 人工点选；上臂/大腿两端铆钉明显 |
| 单轴 + 裙摆 | 大腿摆动时与躯干裙摆相交 | 图层、2~4px 错位、必要时给裙摆做遮罩 |
| 源数据近正面 | 左右角度不一致 | 限位钳制 + 必要时单侧镜像；先以悟空验证 |
| 旧 `adjust.json` 语义变化 | 4 角色需重新标定 | 自动迁移初值 + 标定工具，逐角色验收 |
| 30fps 与全局 45fps | 剧本 / TTS 时序 | 只改每个 Puppet 的帧累加器，不动全局 FPS |
| 素材本身非纯侧面 | 造型仍偏 3/4 | 列为可选美术改造（见 14.2） |

### 14.2 待定项

1. **美术是否改造**：真侧面、单臂、并足。只改骨骼可解决「脱节 + 像人」，但造型仍是 AI 生成的偏 3/4 风格；彻底贴近海宁需要重画部件。
2. **舞台线 `stage_line_y`**：不同背景图 / 视频场景是否需要单独配置？首版按 `stage.jpg` 取一个值。
3. **文角单臂模式**：本期四角色均为武角，接口预留，不实现。
4. **手掌 / 脚掌拆分**：本期不拆；若未来要做腕部细节，再评估。
5. **`leg_mode: glide`**：本期只留字段，不实现传统登角。
6. **动作修整量**：踢腿、跳跃、打戏节奏需要多少手工调整，待 P2 预览后评估。

## 附录 D：大白话版

### D.1 现在到底哪儿不对

把皮影人想成一串用铆钉连起来的皮片子：

- 头插在脖子上；
- 两条胳膊钉在肩膀一个点上；
- 两条腿钉在胯部一个点上；
- 每片皮子只能绕着铆钉转，不能被拉长，也不能飞出去。

现在的程序不是这么干的。它是把 10 片皮子分别“贴”到一套看不见的人体骨架上：胳膊贴到手腕的点、腿贴到膝盖的点，但**皮子本身没有和身体连起来**。所以动作一大，胳膊就可能离开身体，手也可能飘到离肘很远的地方。

再加上素材上两个关节孔之间的距离，和那套人体骨架的骨长对不上（比如上臂的孔距比骨架长了七成），就更容易脱节。以前是靠每个角色手动调偏移量硬“按”回去，但那个偏移不跟着转，一转身就又飞了。

### D.2 要改成什么样

一句话：**给每片皮子打上真正的“铆钉”。**

- 肩膀只有一个点，两条胳膊都钉在这儿；
- 胯部只有一个点，两条腿都钉在这儿；
- 肘、膝只能往一个方向弯；
- 每段皮子的长度就按素材上两个孔的距离算，固定死；
- 这样不管动作多大，部件只能转，不能分开。

这就是真实皮影的做法：打孔、穿线或铆钉，关节是“固定的铰链”，不是“各走各的”。

### D.3 限位是干什么的

限位**不是**为了把动作绑小，而是防止：

- 肘、膝往反方向折（皮子折不过去）；
- 胳膊甩到背后、腿抬到不合常理的角度。

所以数值可以放宽。武角该抬腿抬腿、该踢高踢高，只要**不反折、不脱节**就行。

### D.4 动作怎么办

现在的动作文件记的是“17 个点的位置”。改成记“**12 个受控量**”：

- 身体的位置和转向；
- 头点多少；
- 两条胳膊的肩角、肘角；
- 两条腿的胯角、膝角。

不是“把 17 个点砍掉 5 个”。17 个点是用来量方向的，12 个是真正要控制的量。以前一段骨头两端都记坐标，等于记了两遍；现在只记角度，长度按素材固定，另一端自动算出来，所以不会再拉长或脱节。

好处是：一套动作可以套到不同角色身上。悟空的胳膊长、牛魔王的胳膊短，程序按各自的皮子长度去算，不会出现“牛魔王用了悟空的胳膊”。

### D.5 腿为什么还保留迈步

真皮影没有脚签，走路是脚贴着幕布平移、不迈腿，叫“登角”。那样最像老皮影，但看起来偏“飘”。

你要求灵动一点，所以腿保留驱动：该抬抬、该迈迈、该踢踢，只加三条底线——**不反折、不穿地、不脱节**。真皮影那套“登角”也没丢，留了一个开关，以后做文戏慢走可以切回去。

### D.6 顺带修的两个小毛病

- 现在 30 帧的动作按 45 帧播放，整体快了 1.5 倍；改成按素材自己的帧率走。
- 待机动作首尾差 21px，循环时会跳一下；接缝做一下混合。

### D.7 先做哪一步

先拿**悟空**做样板：

1. 在素材图上点出关节孔、肩膀点、胯点、脖子插口；
2. 让程序按“铆钉”的方式把 10 片皮子连起来；
3. 先放一个待机、一个出拳、一个走路看看。

这一步只新增文件，不动现在的素材、动作和主流程。你看过效果，再决定要不要推广到另外三个角色。
